openapi: "POST /v1/commerce_user_payment_methods"
title: "Create a commerce user payment method"
---

<Note>
  Only for the Commerce API.
</Note>

Apps using the Commerce API can embed Goody's credit card form into their application to allow the app's end users to enter their credit card to save a payment method. Users can then use that payment method to pay for orders.

Call this endpoint to create a payment method associated with a commerce user; provide the user ID as `commerce_end_user_id`. Then, use the returned payment method `id` as the `payment_method_id` in the [Create an Order Batch](/api-reference/order-batches/create-an-order-batch) endpoint along with the `commerce_end_user_id`.

For more information, refer to [Embedded Payment Form](/commerce-api/embedded-payment-form).

## Purchase terms acceptance

If your app shows Goody's purchase terms to the purchaser before they save a card, pass their acceptance as `purchase_terms_acceptance`:

- `accepted_at` (required): when the purchaser accepted the terms, as an ISO 8601 timestamp. Goody stores it in UTC.
- `notification_email` (required): the purchaser's email address, where Goody sends notices about the purchase terms.
- `ip_address` (optional): the IPv4 or IPv6 address of the browser that accepted the terms.

`purchase_terms_acceptance` is optional unless Goody has set up your app to require it. When your app requires it, a request without it returns `400` with `Purchase terms acceptance is required`. When you send it, Goody validates it whether or not your app requires it, and an invalid acceptance returns `400` before the card is saved.
